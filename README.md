# Office documents

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This is a skill package for Miyu. It provides one skill, `office`, which lets the AI write, read and edit Word (.docx), PowerPoint (.pptx) and Excel (.xlsx) files, render pages to images to check the layout, export PDF, and recalculate the formulas in spreadsheets.

The whole runtime is bundled in the package, so it works as soon as it is installed, and you do not need to install Python libraries, Node or LibreOffice separately:

| Bundled component | Purpose |
|---|---|
| Python 3.12 (python-build-standalone) with python-docx, python-pptx, openpyxl, XlsxWriter, pandas, numpy, Pillow and lxml | Writing, reading and editing files |
| Node.js 22 and LibreOffice Kit (`@deepseek-ai/libreoffice-kit`) | Rendering to images, exporting PDF and recalculating formulas |

The LibreOffice engine is the WASM build on Linux and the native build on macOS and Windows.

## Usage

Once the package is installed, just tell the AI what you want, for example "write a weekly report in Word", "work out the totals in this Excel file" or "convert this PPT to PDF". Most of the time the AI only sees the skill's name and a one-line description; it reads `SKILL.md` and the reference for the format at hand only when it uses the skill.

New files get their fonts, font sizes, line spacing and table styles from `officestyle`. Without arguments it uses Arial with Microsoft YaHei at Chinese size No. 5, which suits documents read on screen; fonts and sizes can be passed as arguments, and the AI picks them by document type (SimSun with Times for formal reports, FangSong at size No. 3 for official documents, sans-serif for PPT). Common pairings, a table of Chinese font sizes, the fonts installed on this computer (`tools/fonts.py`), and the fonts the engine substitutes for missing ones are all described in `references/fonts.md`. Without `officestyle`, libraries such as python-docx default to serif fonts (Times, SimSun and the like) with blue headings, which look ugly and blurry on screen. If the user provides a template or wants an existing file edited, the file keeps its original style.

The skill folder is read-only inside the sandbox: scripts, intermediate files and results are all written to the session's workspace. To show a file to a person, the AI first uses the engine to convert it to a PDF with the same name, then calls `show` once for the PDF and once for the original file; the right-hand panel of the web UI can display the PDF directly, while Word, PPT and Excel files only appear as cards you can download. If the user wanted a PDF in the first place, the AI gives only the PDF.

## What the package contains

The package is laid out like this:

```text
skills/office/
├── SKILL.md              # entry point: where the runtime is, when to use the engine, how to deliver
├── references/           # word.md, powerpoint.md, excel.md, engine.md, fonts.md
├── tools/dsoffice.py     # command line that runs LibreOffice Kit with the bundled Node
├── tools/officestyle.py  # styles for new files: fonts and sizes can be passed, default Arial + Microsoft YaHei
├── tools/fonts.py        # lists the fonts installed on this computer (the ones the engine can draw)
└── runtime/              # assembled at packaging time (build/runtime.sh); not in the repository
```

There is one package file per system (`targets`), and all four can be built on Linux. Run:

```sh
build/runtime.sh linux-x86_64     # or linux-aarch64, macos-aarch64, windows-x86_64
```

Every version is pinned: Python and Node are checked against the publishers' SHA-256 hashes, the Python libraries are pinned by `build/requirements.txt`, and the npm packages are checked against the integrity hashes in `build/kit-package-lock.json`. The build uses npm once (the one that comes with the downloaded Node), and what goes into the package is the unpacked files, so users do not need npm.

## Limitations

The skill has these limitations:

- LibreOffice's layout differs from Word, PowerPoint and Excel, mostly in fonts and page breaks. If a document asks for fonts this computer does not have, `missingFonts` in the render result lists them.
- Rendering takes from a few seconds to over ten seconds (the WASM build is slower).
- Old formats (.doc, .xls, .ppt) are first converted to the new formats with the engine and then edited; encrypted files cannot be opened; in files with macros, the macros are neither run nor changed.
